# C06/C07 Corrective Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the provider-neutral Game Agent contract with complete build context and persist/replay non-terminal user decisions without changing BuildService, OpenGame, or UI ownership.

**Architecture:** C06 adds typed Pydantic context/profile/pending-decision values with backwards-compatible defaults and a non-terminal `waiting_for_input` result. C07 adds a `RunPendingDecision` persistence record plus repository/API transitions; waiting runs remain resumable across restart while sequence and SSE replay stay in the existing RunRepository/API boundary.

**Tech Stack:** Python 3.11, FastAPI, Pydantic 2, SQLAlchemy, Alembic, SQLite, pytest, async iterators.

## Global Constraints

- BuildService remains provider-neutral and is not redesigned in this corrective change.
- OpenGame commands, subprocesses, raw logs and adapter types remain out of scope.
- Promote, Publish, Resource Review and Verification decisions remain platform-owned.
- No queue, worker, runtime dependency, Pinia, Vue Router or Workspace UI changes.
- Existing C06/C07 callers remain source-compatible through defaults; new contract tests enforce complete context when supplied.
